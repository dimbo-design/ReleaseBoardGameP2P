# Git-операции, части 1–2 — открытые вопросы по правилам

Перевод [`2026-08-01-git-operations-open-questions.md`](./2026-08-01-git-operations-open-questions.md). Нумерация та же, чтобы вопросы и ответы сходились между версиями.

Что охватывают эти две части: **Git Cherry-pick**, **Inside** (`ai-inside`), **Git Branch**, **Git Merge**. Git Rebase и System Upgrade — более поздние части, здесь их нет.

К каждому вопросу приложена рекомендация. «Согласен с рекомендацией» — полноценный ответ.

Два вопроса (**2** и **12**) помечены как **технические** — они про устройство движка, а не про правила, и ответа от владельца правил не требуют. Они оставлены только для полноты.

## Добор и колоды

- [ ] **1. Что означает обязательный добор в режиме Base, когда колода разделена?**

  [Правила :31](../rules/rules-board-game.md) — «Игрок обязан взять одну карту сверху основной колоды… При разделенной колоде добора карта берется из всех колод.» [Правила :237-243](../rules/rules-board-game.md) задают Base как «Добор из всех колод», а Strategic как «Добор только из одной колоды».

  1. По одной карте с верха **каждой** колоды: при двух колодах игрок за ход берёт две карты. Strategic — одна карта, игрок сам выбирает колоду.
  2. Колоды считаются одним источником: в Base игрок свободно выбирает, откуда взять одну карту, в Strategic он привязан к одной колоде. Количество взятых карт не меняется никогда.

  **Рекомендация: 1.** Таблица режимов имеет смысл только если Base берёт из всех колод — иначе Strategic просто повторяет Base другими словами, а Git Branch ничего не даёт в том самом режиме, который правила называют основным.

  **Это главный вопрос списка.** От него зависит, чем вообще является Git Branch.

- [ ] **2. (Технический вопрос — ответ не нужен.)** Если Base берёт из всех колод, реализовать это одним неделимым действием «добор» или обязанностью «взять из каждой колоды по отдельности»?

  Триггер-карта срабатывает сразу в момент добора и может открыть ожидание решения (Error 503 требует нейтрализации). В движке ожидание может быть только одно за раз. Неделимый добор из двух колод, где первая карта — триггер, потребовал бы очереди ожиданий. Обязанность «по колоде за раз» этого избегает.

- [ ] **3. Разделяет ли Git Branch уже разделённую колоду?**

  [Правила :138](../rules/rules-board-game.md) — «Разделите одну колоду добора (зелёную) на две.» Если карта сыграна дважды: две колоды превращаются в три? Есть ли предел?

  **Рекомендация:** без предела, N → N+1.

- [ ] **4. Где именно проходит разделение?**

  За столом игрок снимает колоду где хочет. В цифровой версии этого выбора нет — если он не нужен по правилам.

  1. Ровно пополам.
  2. В случайном месте.
  3. Игрок выбирает сам — тогда нужен отдельный экран выбора.

  **Рекомендация: 1.** Смысл карты в самом факте разделения, а не в том, где прошёл разрез.

- [ ] **5. Что именно делает sudo Git Branch?**

  [Правила :138](../rules/rules-board-game.md) — «sudo Git Branch: **и** переверните сброс — он будет использоваться как новая колода добора, не перемешивайте карты.» Союз «и» читается как «вдобавок к разделению»: тогда колод становится на две больше — одна из разреза, одна из перевёрнутого сброса (порядок сохраняется, карты не тасуются).

  Это верно, или sudo-вариант заменяет разделение, а не дополняет его?

- [ ] **6. Сбрасывает ли Git Merge уже частично выполненный добор?**

  Актуально только если в вопросе 1 выбран вариант 1. Игрок взял карту из первой колоды, затем сыграл Git Merge — колоды объединились в одну, из которой он уже брал. Должен ли он брать ещё раз?

  **Рекомендация:** нет, обязанность считается выполненной.

- [ ] **7. Что происходит с пустой колодой добора?**

  Если одна из колод опустела, а по правилам режима Base нужно брать из всех — пустая просто пропускается?

  И отдельно: что происходит, когда пусты **все** колоды добора? Замешивается ли сброс обратно, или единственный способ вернуть карты в игру — Git Merge?

## Сброс и информация

- [ ] **8. Сброс открыт всем игрокам?**

  Cherry-pick ([Правила :150](../rules/rules-board-game.md), «выберите одну карту из всего сброса») и Inside ([Правила :163](../rules/rules-board-game.md), «возьмите одну карту Release из сброса в руку») требуют, чтобы игрок видел весь сброс целиком.

  1. Сброс всегда открыт всем — так же, как он лежит на столе рубашкой вниз.
  2. Сброс раскрывается только тому игроку, который сейчас выбирает из него карту.

  **Рекомендация: 1.** Соответствует столу; вариант 2 прячет информацию, которую правила не прячут.

- [ ] **9. Должна ли игра помнить, что игрок знает про колоду?**

  Sudo Cherry-pick кладёт вторую карту наверх колоды добора «не показывая другим игрокам» ([Правила :150](../rules/rules-board-game.md)) — то есть этот игрок знает следующую карту, а остальные нет.

  1. Игра это учитывает и показывает игроку, что он знает верхнюю карту.
  2. Не учитывает: карта легла наверх, игрок сам её помнит — как за столом.

  **Рекомендация: 2 для этой части.** Но отвечать стоит с оглядкой на Git Rebase (следующая часть) — он требует того же самого, только в большем объёме: «посмотрите три верхние карты… и измените их порядок» ([Правила :146](../rules/rules-board-game.md)).

- [ ] **10. На какую колоду ложится вторая карта sudo Cherry-pick?**

  Актуально, только когда Git Branch уже разделил колоду. На первую по счёту, или игрок выбирает сам?

- [ ] **11. Что происходит, если в сбросе нечего взять?**

  Сброс пуст, или — для Inside, который берёт только карты Release — в сбросе нет ни одной карты Release. Карта тратится впустую и ничего не происходит, или сыграть её в такой ситуации нельзя?

## Состав колоды

- [ ] **12. (Технический вопрос — ответ не нужен.)** В каком количестве эти карты входят в колоду и когда.

  Количества уже заданы: System Upgrade 2, Git Merge 2, Git Branch 3, Git Rebase 3, Git Cherry-pick 3. Cherry-pick, Branch и Merge появляются в этой части; Rebase и System Upgrade — нет. Вопрос в том, лежат ли две последние карты в колоде неработающими до своей части или не попадают в неё вовсе.
